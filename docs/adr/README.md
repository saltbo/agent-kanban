# Architecture Decision Records

ADRs explain durable choices that constrain future implementation. Each record
contains the context, accepted decision, consequences, and current status.

Accepted ADRs are not edited to describe a different decision. Add a new ADR
that supersedes the old one. Corrections that do not change the decision, such
as fixing a broken link, remain allowed.

Use a four-digit sequence and a short noun phrase, for example
`0010-example-decision.md`.
